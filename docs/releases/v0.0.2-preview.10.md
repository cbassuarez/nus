# nus 0.0.2 preview 10

## Release summary

- The address is edited where it is: ⌘L / Ctrl+L or a click selects it in the page's header, with suggestions under it (reload, search, history, open ports). Tab selects one part of the address (a docs version, a port, a query parameter) and offers its alternatives. ⌘K stays the palette.
- `nus` is the command on every platform. On its own it opens nus or brings it forward; `nus <file|url>` opens that, starting nus when needed; the remote-control commands now find a running nus from any terminal.
- Linux installs like a Linux app: a .deb for Debian and Ubuntu (desktop entry, icons, Chromium sandbox set up through AppArmor, updates through apt once the repository is enabled), and an archive whose install-desktop.sh installs for one account. Install with `curl -fsSL https://cbassuarez.com/nus.dev/install.sh | NUS_CHANNEL=preview sh`.
- Linux: the launcher icon opens nus (it quit at once), the sandbox check now notices Ubuntu's AppArmor restriction, shells no longer inherit the bundle's library path, and the Chromium library ships stripped (about 1.2 GB smaller unpacked).
- Back and forward (button, Alt+arrows, the swipe) show the page they go to; before, the previous page stayed on screen until a reload.
- Ctrl+T opens a new tab on Windows and Linux wherever it is not a shell's; Ctrl+Shift+T still works everywhere.
- Favicons that would vanish into the theme (a black logo on a dark sidebar) are drawn on a small plate.
- Error pages show the request's route, animated, at their head.

## Validation and boundaries

Local validation on Linux: 650 native-app tests, formatting, 35 packaging
and release tests, the .deb's contents and metadata (desktop-file-validate,
appstreamcli, apparmor_parser), a signed flat apt repository read by apt,
and the installer scripts against a local release. The address field was
exercised through the app's scripted screenshot mode. The release workflow
builds and tests all three platforms and installs, runs and removes the .deb.

The apt repository, the Homebrew tap and winget fill in once their signing
key and tokens are configured (docs/RELEASING.md); until then the .deb and
the one-line installers install the release directly. Mac previews remain
ad-hoc signed.
