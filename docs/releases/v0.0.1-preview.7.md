# nus 0.0.1 preview 7 — candidate review

This is a pre-alpha candidate. These notes describe the intended review scope;
the Release workflow and published `release.json` establish which packages
actually shipped and how each was signed.

## Release summary

- A first-open Atlas arrival with perspective star acceleration and clearer Welcome for new and returning installs.
- Themed pin tiles and a palette-only Start/New Tab option.
- Saved reading copies, resume positions and configured encrypted library sync.
- Procedural sky and stars with approximate Sun and Moon motion.
- Stricter release metadata checks and packaging validation.

## What to review

- **First arrival and returning installations.** The existing centered Atlas
  card hosts the brief first-open sequence. Welcome offers the starting points
  before pin customization, using the app's existing components. Fresh installs,
  redownloads and regular launches have distinct paths. Previous settings are
  offered explicitly; they are not loaded from another build automatically.
- **Start/New Tab and pins.** The palette-only option connects new-tab behavior
  to the existing command palette. Pins support icons or existing live page
  previews and follow the selected corner radius. Reading library is a default
  pin. Welcome uses the correct icon and actual count for its default pin tiles.
- **Personal reading library.** Save pages or editor content, open retained
  copies, find text, adjust reading size and resume. Finishing, archiving,
  removing and refreshing a copy are explicit actions. Saved copies and
  positions participate in configured encrypted sync, including immutable
  article objects; the local writer lock prevents a concurrent local write
  from racing a library exchange.
- **Sky and stars.** Procedural backgrounds retain continuity through pointer
  interaction. The Sun and Moon use approximate orbital calculations. This is
  a decorative sky, not a navigation or precision astronomy instrument; the
  model omits topocentric lunar parallax, refraction, nutation and aberration.
- **Release reliability.** Packaging checks build outputs before replacing a
  Mac bundle and consumes the prebuilt icon generator. Publication validates
  channel metadata and each platform's required stable signing status.

## Data and compatibility

Back up the active profile before trying a pre-alpha candidate. Installation
profiles live under the platform's user-data directory at
`nus/installs/<channel>/<installation>/profile`. Redownload onboarding can
import previous settings; it does not import previous browser data. Source
checkouts continue to use their local profile directory.

Reading-library upgrades preserve legacy entries but write new immutable
snapshot references. Older builds do not understand every new reference or
block type: downgrading the executable does not undo profile changes. Saved
copies are local plaintext. Configured sync encrypts what leaves the device;
it is not a new account service or automatic cross-device setup. Removal keeps
records and objects and is not secure deletion. See the detailed
[capture, storage and reader boundaries](../READING_LIBRARY_REPAIR.md).

Capture copies only bounded, already-loaded, origin-clean images. It cannot
bypass image origin restrictions or guarantee a complete copy of every page.
An unavailable copy remains a visible link with an explanation; opening the
original is explicit. Re-saving preserves an existing copy and its position;
refresh deliberately replaces the copy.

## Evidence and remaining boundaries

The release-script suite covers publication ordering, corrupt/missing artifacts,
immutable published releases, scoped previews, channel/signing validation and
Linux archive contents. Native application tests, capture fixtures and storage
tests answer different questions; none alone establishes clean-machine desktop
acceptance. Build both Cargo workspaces with their lockfiles, including the app
helper, CLI and hold process, against the candidate commit.

Windows/Linux native behavior, assistive technology, mixed-scale displays,
large-library performance and simultaneous edits across independent devices
remain separate acceptance areas. Mac ad-hoc signature verification is not
Developer ID notarization or a Gatekeeper result. The earlier
[security and release audit](../RELEASE_AUDIT_2026-09-20.md) is historical context,
not a fresh security clearance for this candidate. In particular, a Rust test
run does not establish current Chromium security coverage.

Reviewers should report the exact release tag, OS, signing label and whether
they used a fresh, redownload or existing profile. Avoid attaching private
reading snapshots, browsing history or credentials to an issue.
