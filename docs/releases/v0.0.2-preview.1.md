# nus 0.0.2 preview 1

The first 0.0.2 candidate. It carries everything prepared as 0.0.1 preview 10,
which was never published, and a new Windows installer.

## Release summary

- **A new Windows installer.** One page instead of four: where nus installs (just for you, no admin, no restart) and what it adds to Windows: the `nus` command on PATH (on), nus listed as a browser in Default apps (off) and a desktop shortcut (off). Updates show the same page with your last choices on one line; untick one and it is taken back out. If nus is open, Setup asks once and closes it. Uninstall asks whether to keep your settings.
- **Assistants in the sidebar (the Ledger).** A tab running Claude, Codex or another assistant shows what it is doing under its title: working with its elapsed time and current tool, waiting with the question it is asking, or done with the files it changed. Claude's permission prompts can be answered from the sidebar (Allow, Deny, Always); the answer is the keystroke the assistant's own prompt takes, so the terminal and the sidebar stay in step. The top strip counts waiting and working assistants.
- **`nus hook`.** Assistants report through their own hook systems: `nus hook install claude|codex` adds nus's hooks beside the user's (a backup is kept; `uninstall` removes only nus's). Settings · Assistants · Connections offers the command for review. Programs that send desktop notifications (OSC 9, OSC 777) are shown as waiting with their words.
- **One profile per channel.** Rebuilt, redownloaded and moved copies share `installs/<channel>/shared` instead of starting over. The most recently used profile moves in on first launch when no nus holds it. A copy can keep its own profile (Settings · Updates · Profile). Welcome shows once per version.
- **Home.** Clicking a row opens that row (rows naming other tabs were missing while the frame drew, so clicks landed one row early). The `nus` wordmark is a latched button: press for home, press again or go back to return. The home line and the palette follow CURSOR's shape, color, blink and weight.
- **Stopping processes.** The ports board's stop button opens the row so its confirmation is visible; before, a stop that needed confirming did nothing.
- **Back and forward.** The swipe overlay has styles (arrow, arrow and words, edge band, none) and distances, shows where a swipe goes or that it goes nowhere, and one swipe no longer fires twice.
- **Panes and windows.** Layout changes go through one director with undo and redo; pane mode (Ctrl+Alt+P) and drop zones move and swap panes; tabs move between windows with their shells and pages intact.
- **Shell colors** from the theme's signal family, in OKLCH, by random choice or by folder.
- **Finish Work.** The coffee in the header keeps the machine awake until work you started finishes, then gives power management back.
- **Interstitials.** Error, warning and interruption pages read as a shell transcript, with the safe command as the default.
- **Intelligence.** One level, Instant to Max, for assistant launches, shown as an atom in Settings · Assistants.

## Speed and reliability

- Breathing marks and ticking counts no longer redraw the window every frame;
  they ask for the frames they need (ten a second for breathing, one a
  second for clocks). The Ask panel's thinking dot does the same.
- The home line measures each character once per frame instead of once per
  edge; long lines no longer cost quadratic time.
- The library and sync writer locks wait out the moment a forked process
  (the ports scan, a shell) keeps a copy of the lock, instead of reporting
  the library busy. This also removes the intermittent `library_store` test
  failures.
- Background tabs track what they are running; a long command that wrapped
  in a narrow pane is no longer misnamed.
- Held shells: a test confirms closing a tab ends the shell and everything it
  started.

## Windows

Windows packages are signed by Azure Artifact Signing in the release
workflow's `sign-windows` job, and the per-user installer is signed the same
way. This is the first release through that path; `release.json` records the
outcome.

The installer (`scripts/windows-installer.iss`) is one Broadsheet sheet with
the channel's masthead. `/TASKS=` names are `path`, `browser` and
`desktopicon`; `path` is now on by default. Browser registration is per-user
(StartMenuInternet, RegisteredApplications and an http/https handler), and
Finish offers Default apps, since only the user can choose a default browser.
When nus is running, Setup asks its windows to close, then stops what is
left, held shells included; an installer update ends running shells, as it
did before. The release job installs with `path,browser`, installs again with
`path` alone, and uninstalls, checking PATH and the browser registration each
time.

## Review boundaries

Assistant hook event names, payload fields and permission keys are nus's
understanding of Claude Code's and Codex's formats; they were exercised end to
end with stand-in programs, not live assistant sessions, and may need
adjusting against current versions of those tools. Codex has no sidebar answers.
Native checks ran on macOS; the release matrix builds and tests all three
platforms.

The installer was compiled with Inno Setup 6.3.1 for both channels and run
under Wine: silent install, update and uninstall; the sheet, update and
reinstall states; the open-app dialog and the uninstall dialog. On real
Windows, detecting nus by its install folder (WMI `ExecutablePath`, missing in
Wine) and nus's response to the close request were not exercised before this
candidate. The uninstaller itself is not yet signed; the uninstall progress
window keeps Inno's stock look.

## Update note

Save active work before installing. Updates can interrupt running processes,
and an installer update ends shells nus is holding. The first launch moves the
channel's most recent profile into the shared location. Exact package hashes,
source revision and signing status are in `release.json`.
