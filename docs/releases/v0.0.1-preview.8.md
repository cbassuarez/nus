# nus 0.0.1 preview 8

## Release summary

- Plot replaces local-site warning tape with four corner markers and quiet survey lines, including matching address and status marks.
- Radiance adds a continuous loading bar with a real HDR highlight on supported native surfaces; stalled loads hold their position and completed loads settle without idle redraws.
- First-window profile onboarding opens automatically again, without repeating in secondary or completed-profile windows.
- Unified reading lists, saved commands, Markdown/JSON/CSV/text viewers, import flow, and Station Port Control improvements.
- Video PiP follows the stream aspect ratio and offers configurable leave/return behavior.
- GitHub update discovery, explicit installation, retained-package recovery, versioned profiles and component compatibility checks.
- Local Mercury claims, encrypted nus-owned sensitive state, local secret redaction, and cross-platform process/file handling fixes.

## Plot and HDR

Plot denotes a local or private-network destination, not a security sandbox or a
claim that the page is trusted. URL parsing handles loopback IPv4, IPv6, local
hostnames and private addresses; a remote hostname containing “localhost” does
not qualify. The marks stay within their own pane and do not intercept input or
change page dimensions. They remain when navigation finishes or the page sleeps.

Radiance is available in Settings → Browser → Loading bar. Existing saved style
choices remain intact. New default and formerly comet-based theme presets use
Radiance. Progress comes from Chromium and does not trickle forward during a
stall. Reduced motion applies directly reported progress.

The renderer selects RGBA16Float with ExtendedSrgbLinear only when the native
surface advertises that combination. Existing UI and browser textures are
converted from sRGB; Windows scRGB output accounts for the OS SDR-white level.
Unsupported surfaces retain SDR output. Available HDR brightness is controlled
by the OS, compositor, display and user settings. PNG captures remain SDR and
must not be used as proof of HDR luminance.

## Profile and process continuity

The first primary window with incomplete onboarding and no saved profile opens
the existing profile flow beneath the first-arrival animation. Declining it does
not silently complete Welcome. Secondary windows and completed introductions do
not reopen it automatically.

Sensitive nus-owned records use authenticated encryption with keys in the OS
credential store. When starting a holder, the parent resolves the profile key
before spawning and passes it through that child's anonymous stdin pipe. The
helper retains it only in memory; it is never placed in command arguments,
environment variables or ordinary files. This avoids a second keychain prompt
for each shell helper. Failure to unlock the parent vault remains fail-closed.
Startup failures stop the new helper instead of leaving an unattached process.

See [local security](../LOCAL_SECURITY.md), [managed runtime design](../MANAGED_AGENT_RUNTIME.md),
[multi-version support](../MULTI_VERSION_SUPPORT.md), and
[update limitations](../UPDATES_AND_MERCURY.md). The managed runtime document is
a design, not a claim that independently launched agents are already sandboxed.
Automatic process resumption is still experimental and not extensively tested.
Updating can interrupt active work; save it before installing.

## Verification

The candidate is checked in both Cargo workspaces, including the rebuilt holder,
and by the release-metadata tests. Native macOS fixtures exercise fresh and
returning startup, secondary windows, first-profile presentation, Plot at wide
and narrow widths, progress hold, completion and idle behavior. HDR validation
checks surface selection and reads floating-point pixels from the actual
radiance shader alongside an SDR-white reference. Screenshots check geometry.

The Release workflow establishes the actual shipped revision, platform matrix,
package hashes and signing status. Native HDR display behavior on Windows and
Linux requires testing on those machines; compilation does not establish it.
Preview signing/notarization status is reported per package in release.json.
