# nus 0.0.2 preview 11

## Release summary

- Linux: nus no longer freezes. Frames were presented with vsync, and on Wayland that blocks the thread that also handles input and the close button while the compositor holds the window's buffers; Linux now presents without blocking.
- Linux: nus cannot starve the machine. The launcher runs nus and every Chromium process it starts in a systemd scope of their own: memory above 30% of RAM is reclaimed from nus first, 50% is a hard ceiling, and nus takes half a normal CPU share under contention. If the machine runs out of memory anyway, nus is first to go.
- Linux: a menu entry left by an older or deleted copy no longer keeps the menu from opening the installed nus.
- Buttons on the theme's signal colour are labelled in whatever reads on it: LET'S BEGIN on the first-run card was white on white in Blueprint.
- The install command shows the nus wordmark settling into place, then each step (found, download, verify, install) with its time, a live download bar, and the package manager's output in a small window that folds away. Run again, it updates, or says nus is up to date.

## Validation and boundaries

Local validation on Linux: 652 native-app tests, render tests, formatting,
the release tests, the launcher's scope limits in a live run, the present
mode in a live run, and both install scripts in a pseudo-terminal against a
local release (with a stand-in for sudo and the Windows installer), plain
output when piped, and ASCII output without a UTF-8 locale.

The scope needs a user systemd session; without one nus runs as before. The
present mode is Mailbox where the driver offers it, Immediate where that is
all there is, and vsync otherwise. macOS and Windows present as before.
