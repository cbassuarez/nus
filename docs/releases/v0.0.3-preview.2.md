# nus 0.0.3 preview 2

## Release summary

- Notes are set as written, in any face. Text wraps at the column, list items hang under their words, lines are numbered in the margin, and the caret, clicks and Up/Down follow the real letters, so proportional faces such as Areal no longer drift. Off the caret's line the Markdown reads as a document (live preview): headings larger, bullets, boxes you can tick, quote bars, links as their words. Read view and Focus are on the rail, in the palette and on ⌘⌥R / ⌘⌥F (Ctrl+Alt elsewhere).
- The header's note button opens a picker: a new note, notes open in another tab or window, recent notes, and a search. A fresh tab becomes the note; a page or shell beside is never closed. A note opened beside another pane appears at once.
- NOTES in the sidebar, where the menu drawer's button was: open tasks across this project's and your personal notes (tick them there), the notes, and their tags; a tag narrows the page to its notes.
- `[[` links notes by name, `/` at a line's start makes headings, lists, checklists, code and more, and `![[…]]` embeds another note, a file's lines, a page (with its live title) or a captured clip by reference, live, saying when the source changed.
- The formatting rail names every button and its keys, and as a row it no longer sits under a split pane's controls. A crash now leaves its cause in nus.log.
- nus can be see-through on Windows too (DirectComposition swapchains). OPACITY applies by region as LOOK says (panes, chrome too, or the whole window), and pages paint white where they paint nothing, as in Chrome.
- The download peek: a download you start sits on a shelf above the sidebar's foot until you look, saying how far it is; with the sidebar hidden the foot slides out with it.
- Sites can notify: pages get a Notification API that fills the tab's cell, puts the words on its row and rings the Dock, as each site is allowed (ask, count only, show, off).
- The anchor: one pane a window keeps beside every tab until it is let go.
- File viewers: Markdown, PDF, JSON, CSV and plain text can be opened by the system in nus, each kind only when asked for in FILE VIEWERS.
- A repository is its own notes project, even inside a folder that has notes. A private file not yet written (a new personal note, a first save under the profile) is recognized as private on Windows, so it is sealed and kept from language servers.

## Validation and boundaries

The candidate passes root-workspace formatting, Clippy and tests, and the
native-app tests (721 passed, four explicitly ignored), with the browser
media transport and rapid PiP checks. Notes, transparency regions and the
NOTES page were exercised in a debug build of the app through its own
in-process shot driver (scripted input on its event loop, captures of its
own frames) against disposable profiles on Windows: wrapping and caret
placement in Areal, live preview, Read view and Focus, the picker, ticking
a task from the sidebar, `[[` links, the slash menu, note, file, page and
clip embeds, and tags. Region opacity was measured from straight-alpha
captures; the composite of a see-through window over the desktop was not
captured, and rail tooltips were not seen on screen (captured windows are
unfocused).

The download peek, site notifications, the anchor and file viewers come
from separate work sessions and are covered by their own tests and shots;
they were not re-reviewed for this note. None of this was checked in an
installed release build before tagging.

The Release workflow builds and tests macOS arm64, Windows x86-64 and Linux
x86-64, then exercises packaged browser rendering and native failure recovery.
Publication requires every platform job to pass. Windows packages and the
installer require Azure signatures and install/update/uninstall checks. macOS
remains an ad-hoc signed preview while notarization credentials are incomplete.
The published workflow and `release.json` establish the actual package revision,
checksums and signing outcome.
