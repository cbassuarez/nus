# nus 0.0.3 preview 3

## Release summary

- Chromium 156. The browser is CEF 156.0.14 (Chromium 156.0.8078.48) in place of CEF 152.0.6: four milestones of Chromium's security fixes. Rust dependencies are at their newest compatible versions, and every RustSec advisory with a fix is cleared (rustls, rustls-webpki, webpki-roots, tokio, zip). nus embeds neither PHP nor Tailscale, so October's PHP and Tailscale advisories do not apply to it.
- Notes scroll. A note made of long paragraphs could not be scrolled at all. The wheel, a touchpad (small turns now add up), Ctrl+↑/↓ and Page Up/Down move by the rows on screen, and the end of the note stops at the foot of the column. ↑/↓ at the column's edge move a row instead of jumping a paragraph, and Home and End go to the ends of the row on screen.
- Every character types. AltGr on Windows and Linux (`@ { } [ ] \ |` on many layouts) and Option on a Mac (`– … é`) type in notes and code instead of being taken as shortcuts.
- Long notes are lighter to type in: their lines are measured once instead of on every frame.
- A page you are reading is no longer called unresponsive. The "Page unresponsive" sheet appears only when a click or key has gone unanswered, as in Chrome. Pages hear of system memory pressure once as it rises, not every 30 seconds while it lasts; each of those notices made every page stop to clear its memory, which is what made a mail or a PDF miss the heartbeat on a machine short of memory.
- Terminals keep their text: over a long session the glyph atlas filled and terminals went blank. It now starts over when full.
- New tabs open under the current one and its stack (WHERE NEW PAGES OPEN · A NEW TAB GOES; the end of the list is still a choice).
- The closed hatch, where there is no camera housing, is a tab hanging from the top of the screen with one lamp per piece of work: a breathing square while it runs, filling with progress, a diamond when it needs you, a circle or a hatched square when it finished or failed. On a notched Mac the island's wings carry the same lamps.

## Validation and boundaries

The candidate passes root-workspace formatting and the nus-render tests and
Clippy on this machine, the native-app tests (728 passed, four explicitly
ignored), the browser media transport and rapid PiP checks, and the release
packaging tests; the CI workflow ran the full gate on Windows, macOS and
Linux for the change commit. Chromium 156 was exercised in a Windows release
build staged as the packaged bootstrap (sandbox on): a local page, a PDF in
Chromium's viewer, and the hang watch (an idle page after a forced critical
memory notice and a page stuck in a loop are left alone; a click on the
stuck page raises the sheet after ten seconds). Notes scrolling, paging,
row-wise ↑/↓ and Home/End, a click placing the caret and touchpad
accumulation were exercised through the app's own shot driver (scripted
input on its event loop, captures of its own frames) on Windows. AltGr and
Option typing were not exercised with a real keyboard layout, and a real
wheel and touchpad were not used. The royalty-free macOS CEF build script is
pinned to CEF 156 and its two patches were checked against Chromium 156's
sources; it was not run.

The terminal atlas and new-tab placement are covered by unit tests and were
not reproduced live. The hatch lamps were checked from the app's own
captures on Windows; not yet on a notched Mac or Linux. None of this was
checked in an installed release build before tagging.

The Release workflow builds and tests macOS arm64, Windows x86-64 and Linux
x86-64, then exercises packaged browser rendering and native failure recovery.
Publication requires every platform job to pass. Windows packages and the
installer require Azure signatures and install/update/uninstall checks. macOS
remains an ad-hoc signed preview while notarization credentials are incomplete.
The published workflow and `release.json` establish the actual package revision,
checksums and signing outcome.
