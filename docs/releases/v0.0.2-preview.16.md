# nus 0.0.2 preview 16

## Release summary

- Kept brings bookmarks, reading, saved copies, keywords, pinned pages and collections into one record. Kept items lead address and palette results; `said:<word>` searches saved copies.
- Tab rows show where each tab is and whether it is running, listening, waiting, finished, playing or edited. Orrery and tab dragging make the workspace easier to arrange.
- Find works across pages, shells and editors, with whole words, patterns and a wider search when the current pane has no answer.
- `nus version`, `update`, `doctor`, `uninstall`, `channel`, `logs` and the sync commands expose installation and encrypted-profile management from the shell.
- Linux and Windows close and quit correctly without stray console windows. Linux's dock and tray use the launch animation; animation frames follow the display's pace.
- Invalid keyword input keeps the previous keyword and leaves the editor open for correction. Unicode keywords obey the same size limit as stored records; clearing the field still removes a keyword deliberately.
- A local “Here” profile continues across updates, reinstalls and moved copies without sync. Legacy-profile migration stops if the profile is busy or cannot be moved, preserving it instead of creating a duplicate.
- `nus uninstall --everything` removes the channel's profiles, recovery copies, vault keys and logs. Windows' **Remove them too** option does the same; normal uninstall keeps the profile for reinstall. Other channels, projects and remote sync folders are preserved.
- Completed updates remove their temporary download and staging folders. Complete uninstall also removes retained app packages owned by that installation, while preserving unrelated neighboring folders.
- Linux complete uninstall purges apt configuration and removes an account installation's owned sandbox rule. The shared GNOME dock extension and marker are removed once no other installed channel needs them.
- Windows legacy-profile migration keeps the open lock file in place, moves the live profile last, and rolls back earlier moves if migration fails.
- Package instructions point to the shared channel profile. A rejected download-site dispatch now fails visibly in Actions.

## Validation and boundaries

Before tagging: locked root-workspace tests, native-app tests
(696 passed), root formatting and Clippy, 33 release tests and 39 script tests,
and browser media transport and rapid PiP checks passed on macOS. The new native
keyword regression checks invalid input, Unicode storage limits, persisted
values and deliberate removal through the real palette keyboard path.

The Release workflow runs release-mode tests and packaged browser rendering,
timeout, crash, hang and retry checks on all three platforms. It also runs the
keyword regression on each packaged app. Windows publication requires Azure
signatures on the five executable payloads and installer, followed by installer
install, upgrade, native launch, reinstall, profile continuity, normal uninstall
and complete-cleanup checks. Local regressions cover Here without sync, locked
and failed migrations, busy-profile cleanup, recovery removal, linked paths and
vault credentials still used by another channel. The workflow result and published
`release.json` are the evidence for platform packaging and signing.

macOS remains an ad-hoc signed preview while Apple notarization credentials
are incomplete. Package-manager and download-site dispatch steps require their
repository credentials; a skipped optional integration does not prove it updated.
