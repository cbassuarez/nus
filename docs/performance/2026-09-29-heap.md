# Heap optimization follow-up — 2026-09-29

All changes are uncommitted. This follows the [home-motion investigation](2026-09-29-home-motion.md).

## Implemented

- **Borrowed text-cache keys.** Shape/width lookups no longer construct owned
  strings on hits. The full font, size, tracking and text identity is retained,
  as are second-chance eviction and existing entry/weight limits. Regression
  tests cover distinct fonts/sizes/tracking/text, reclamation, and zero allocations
  across 1,000 warmed shape/width lookup pairs.
- **Bounded polygon reuse.** Per-artwork scratch pools retain at most 128 buffers
  and 256 KiB of point capacity. Commands return storage when drawn or discarded,
  including script-error paths. Flat coordinate pairs compact in place. Existing
  2,048-input-point, 8,192-command and 4 MiB command limits still apply. Idle scratch
  is released after ten seconds at the next maintenance tick, and memory pressure
  reclaims it immediately. Active Lua state is retained to preserve animation.
- **Memphis table reuse.** Invariant contours are created once. Animated squiggle,
  stripe and transformed points reuse tables; squiggle construction no longer
  inserts repeatedly at the front of a list. Rotations compute sine/cosine once
  per piece. The pointer and signal table are fetched once per draw/VM respectively.
- **Shared prompt rows.** Home stores reference-counted row snapshots and uses
  fixed-size preparation for its two panes. Two bounded cache entries prevent
  alternating split queries from evicting each other. Exact structural snapshots
  replace per-frame debug formatting. Settings, assistant configuration, working
  directories, active tab, title, identity and order invalidate immediately;
  external sources still refresh every 500 ms. This uses exact comparisons instead
  of a revision counter, avoiding missed invalidations across scattered mutations.
  Obsolete place-row gathering whose result was ignored was removed.
- **Software browser bindings.** Each view/popup texture owns its reusable binding.
  Resize replaces the texture and binding together; ordinary paints clone only
  the binding's Arc. This does not change accelerated-surface ownership.

## Additional hotspots found and addressed

Allocation-stack sampling showed `color_of → LuaString::to_str →
ValueRef::clone_shared → Rc::new` during almost every drawing primitive.
Immutable color strings now use a cache of at most 64 entries, each retaining a
string no longer than 64 bytes. The owning Lua string reference prevents pointer
reuse while cached. Alpha is applied separately for every command. Mutable color
tables bypass the cache. Reload clears it before the old VM is replaced, and
memory pressure/idle reclamation clears it too.

Capitalization no longer collects a temporary character vector for each word.
Working-directory lookup no longer collects a temporary pane vector. Ordinary
non-editor tab-title comparisons write into an exact string comparator instead
of allocating temporary titles. Theme clones were inspected: their fields are
value data, so replacing those would not eliminate heap allocations.

## Further opportunities identified

Items 1 and 2 below are now implemented; see the text follow-up below. Items 3
and 4 remain candidates or measurement limitations.

1. `App::fit_by` always returns an owned string, even when text fits. Truncation
   also constructs a character vector and multiple candidate strings. A borrowed
   fast path and reusable candidate storage should be measured across actual
   header/sidebar/editor workloads, preserving Unicode and ellipsis behavior.
2. Tracked text still creates its case-transformed output string. A small bounded
   transformed-text cache could help static labels; the per-word vectors are
   already gone. Text-cache insertion also clones an owned key into its eviction
   queue; shared string ownership could reduce cold-cache allocation traffic.
3. The remaining Memphis samples include per-frame interrupt-callback and canvas
   setup. Reusing those is a smaller candidate than layout/text churn and must
   preserve time budgets, reload behavior and script isolation.
4. Video/Metal/native allocations and retained memory still need a working
   Instruments attachment and Windows/Linux profiling. Reusing bindings removes
   a specific redundant operation; it does not establish cross-platform streaming
   smoothness or total-memory savings.

## Text follow-up

The text-fitting API now returns borrowed text when the label already fits and
accepts owned temporary strings without copying them again. Truncation retains
one candidate buffer throughout bisection plus one exact-sized character buffer;
it preserves the old character-count search, ellipsis and 0.01-pixel tolerance.
Callers that retain strings explicitly take ownership. Other call-site changes
transfer formatted temporary strings into the fit operation directly.

Tracked labels share case-transformed strings across measurement and drawing.
This cache is bounded to 512 entries and a 64 KiB input/output text-byte budget
(plus bounded map/queue metadata); strings over 512 input bytes bypass it. Font
cache reclamation also clears this cache. It keys by source text because the
case transform is independent of font, size and tracking. Shaped/width-cache keys
now use shared string ownership, so the eviction queue does not duplicate their
text on insertion. Existing cache identities, entry limits and weights remain.

| Scoped operation, 1,000 iterations | Before allocation calls | After allocation calls | Before requested bytes | After requested bytes |
| --- | ---: | ---: | ---: | ---: |
| Warmed tracked-label measurement | 1,000 | 0 | 23,000 | 0 |
| Cold width-cache insertion, shaping prewarmed | 2,001 | 1,001 | 279,480 | 240,712 |
| Truncation of the same warmed label | 24,000 | 2,000 | 864,000 | 299,000 |

Already-fitting borrowed labels and transferred owned labels allocate zero in
the warmed test. Warmed tracked-label **drawing** also allocates zero after
preparing glyphs and scene capacity. This is not a claim that cold glyph uploads,
arbitrary dynamic labels or the entire native frame allocate nothing.

The previous fitting algorithm serves as the behavioral oracle. Tests cover
proportional-font kerning/ligatures, tracked labels, accents, combining characters,
CJK, emoji sequences, whitespace, negative/tiny widths, infinity and exact-fit
tolerance. They also verify case-cache sharing, oversized bypass, bounded
retention and reclamation. All 35 renderer library tests, 6 allocation/behavior
integration tests and 580 composite tests passed (3 composite tests ignored).
The measured allocation traffic is separate from total retained memory; the new
label cache deliberately trades a bounded amount of retention for less churn.


The optimized build and fresh-profile native UI check also passed. The native
check covers prompt-cache behavior, Settings navigation, a narrow window with
accented/CJK/emoji input, and animation recovery after critical memory pressure.
The narrow screenshot confirms fitting/ellipsis layout; it does not establish
emoji glyph fidelity. Evidence: `/tmp/nus-text-ui-check.log` and the native
capture directory recorded in the companion JSON.

A 10-second Memphis run on battery retained the intended approximately 30 Hz
