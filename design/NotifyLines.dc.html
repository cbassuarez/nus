C · Lines

A line per service, and one switchboard. A line is a small signed Luau file that knows one site: where Gmail keeps its important count, which Slack dots are to you, when the next meeting starts. It speaks in channels, and the switchboard decides where each channel may sound. While you’re busy, notices are held and come back as one digest.

a line · knows one service; reads, never clicks

-- lines/slack.luau · signed, from the gallery
line { site = "app.slack.com", v = 7 }

function read(doc)
  local you = doc:count(".p-channel_sidebar__badge")
  local all = doc:count("[data-qa=unread]")
  return { to_you = you, count = all,
           title = doc:text(".p-view_header__channel_title") }
end

function notice(n)          -- the page’s own Notification
  local dm = n.tag:find("^D")
  return { channel = dm and "to you" or "channels" }
end

How it reads. Slack says “to you” or “channels”, not just a number, and you decide once where each one goes. Typing in a shell holds everything except failures, and the hold lets go as one digest.
How it works. A page line runs in its page as a boost (on_page, read-only DOM helpers, no clicks, no network). A source line gets http.get only to the hosts it declares. Every notice gets a channel, and lines without one fall back to A’s generic signals.
For. The sharpest signal: real “to you” versus noise, per service. The switchboard and the hold are worth having even with no lines, because shells and assistants use them too.
Against. Lines break when sites change (Ferdium’s recipes do, often), so someone has to maintain the gallery. Most configuration of the three. Pages still have to be open: lines read pages, they don’t replace them.
