What all three share. The bounds, the timings, and one model of a drag: a single intent that the ghost, the target and the words all draw from. The directions differ only in how a verb is chosen: by place (A), by waiting (B), by key (C).

One Intent {verb, target, preview} computed per pointer move, drawn by one painter, applied by one function: the director. The ghost, the chip, the target's wash and the bar all read the same Intent, so they can't disagree.
Wayland (your session: GNOME 50.1). Today a tab let go outside the window always opens a new window: outer_position isn't available on Wayland, so dropped_outside can't find another nus window under the pointer. The in-window routes (A's shelf, B's sprung name, C's digits) fix this on every platform. A true tear-off that follows the pointer needs xdg-toplevel-drag-v1 — Mutter has it since 48, KWin too — but winit 0.30 has no drag source, so that is our own wl_data_device code alongside winit: a later step.
Keys. shift for join: free on every desktop, and VS Code already uses shift to change what a drop does. ctrl for copy: Firefox duplicates a tab on ctrl-drag; Windows and Finder copy on it. Never alt or super: on Linux those drag the whole window (GNOME's mouse-button-modifier is super; others use alt). esc always cancels.
